# RAI Risk Taxonomy 2.0 재구축 작업계획서

## 1. 목적

이 재구축은 기존 결과를 수정하는 방식이 아니라 2026-08-26 KTSPACE 원천 CSV를 동결한 뒤 L4 정제와 L3 매핑을 처음부터 다시 수행한다. 핵심 목표는 주제, 활동, 적용 영역, 정책대상을 L4 리스크로 오인하는 문제를 제거하고, 학술문헌, 정책보고서, 법령 및 공신력 있는 가이드라인에서 사용하는 표준 용어와 L3 마스터의 문체에 부합하는 L4 리스크 카드만 유지하는 것이다.

기존 마스터 릴리스와 기존 업그레이드 프로젝트는 비교 기준으로만 사용하며 수정하거나 덮어쓰지 않는다.

## 2. 기존 오류에서 도출한 재설계 원칙

### 2.1 리스크 적격성 검증이 의미적 매핑보다 선행해야 한다

기존 파이프라인은 모든 L4 입력을 리스크라고 가정하고 곧바로 L3 의미 공간에 투입했다. 이로 인해 `응급·재난 대응`처럼 적용 맥락만 기술한 항목도 가장 가까운 L3에 강제로 배정됐다.

새 파이프라인은 먼저 L4가 다음 요소를 갖춘 리스크 진술인지 검증한다.

1. AI 시스템, 모델, 에이전트, 운영자 또는 AI 활용 과정이라는 위험 주체
2. 실패, 오용, 부적절한 출력·판단·행동 또는 통제 결함이라는 위험 메커니즘
3. 권리 침해, 안전 저하, 피해, 위해 또는 부정적 결과
4. 위험 메커니즘과 결과 사이의 명시적 인과관계
5. 개인, 집단, 조직, 사회, 환경 또는 시스템이라는 영향 대상

주제명, 적용 분야, 정상 기능, 보호적 활동 또는 평가대상만 서술한 항목은 L3 매핑에 진입하지 않는다.

### 2.2 유사도는 리스크 적격성과 범주 함의를 대신할 수 없다

임베딩 유사도는 후보 탐색에만 사용한다. 최종 자동 배정에는 L3 정의의 필수 의미조건을 충족하는지 확인하는 제약조건 검사가 추가된다. 예를 들어 Violence는 폭력 조장, 정당화, 미화 또는 위해 실행 지원 중 하나가 명시되어야 한다. 생명, 안전, 응급, CPR 같은 관련 어휘만으로는 Violence에 배정할 수 없다.

### 2.3 수치적 안정성과 의미적 타당성을 분리한다

다중 seed에서 동일한 결과가 나오는 것은 계산 안정성이다. 해당 L3의 개념을 충족하는지는 별도 검증한다. 높은 stability만으로 자동 승인하지 않는다.

### 2.4 계보 연결은 `source_row_id`만 사용한다

`new`처럼 중복 가능한 기존 L4 ID를 조인키로 사용하지 않는다. 원천을 읽는 순간 도메인별 고유 `source_row_id`를 발급하고, 삭제·통합·분리·수정·최종 ID 발급의 모든 계보는 이 키로 연결한다.

## 3. 변경 불가 기준

1. 원천 CSV와 PDF는 `00_source_snapshot`에 보존하고 SHA-256을 검증한다.
2. L3 마스터 46행의 ID, 명칭, 정의 및 계층은 변경하지 않는다.
3. 파생 Others 3개만 허용하며 새로운 실질 L3는 생성하지 않는다.
4. Instruction Prompt와 L3 마스터가 충돌하면 L3 마스터를 우선한다.
5. `facet`과 `act-type`은 L4 속성으로 보존하고 의미적 매핑 입력에서는 제외한다.
6. 원천의 인간 수정 설명이 유효하면 원문보다 우선한다. 단, 잘못된 언어, 빈 값, 비문 또는 리스크 진술이 아닌 경우에는 사유를 기록하고 사용하지 않는다.
7. 기존 마스터와 기존 프로젝트는 덮어쓰지 않는다.

## 4. L4 판정 체계

각 원천 행은 다음 상태 중 하나로 판정한다.

| 상태 | 의미 | 처리 |
|---|---|---|
| `KEEP_AS_IS` | 명칭과 정의가 이미 완결된 리스크 진술 | 최소 정규화 후 유지 |
| `REWRITE_KEEP` | 위험 메커니즘이 식별 가능하지만 명칭·정의가 주제형 또는 비표준 문체 | 표준 용어로 재작성 후 유지 |
| `SPLIT_REWRITE` | 독립적인 위험 메커니즘이 둘 이상이고 원천 지시 또는 인간 결정이 분리를 승인 | 자식 카드로 분리하고 계보 보존 |
| `MERGE_REWRITE` | 원천 지시가 특정 카드 통합을 명시 | 통합 후 표준 명칭·정의 작성 |
| `DELETE_NON_RISK` | 정상 기능, 적용 영역, 보호적 활동 또는 단순 대상이며 고유 위험 메커니즘을 합리적으로 복원할 수 없음 | 최종 L4에서 제외하고 삭제 아카이브에 보존 |
| `DELETE_DUPLICATE` | 다른 카드와 위험 메커니즘·영향·범위가 실질적으로 동일 | 대표 카드에 계보 연결 후 제외 |
| `HD_REVIEW` | 수정 가능성과 삭제 여부 또는 L3 배정이 불명확 | 최종 자동 매핑에서 제외하고 인간 결정 대기열로 이동 |

### 4.1 수정 후 유지 조건

다음 조건을 모두 충족할 때만 `REWRITE_KEEP`으로 처리한다.

1. 원천 문장에서 구체적인 AI 관련 위험 메커니즘을 직접 추출할 수 있다.
2. 위험 메커니즘을 새로 발명하지 않고도 부정적 결과를 명시할 수 있다.
3. 수정된 카드가 기존 카드의 단순 중복이 아니다.
4. 한글과 영문이 동일한 개념 범위와 인과관계를 가진다.
5. 최소 하나의 기존 L3 정의와 개념적으로 양립할 수 있다.

하나라도 충족하지 못하면 `DELETE_NON_RISK` 또는 `HD_REVIEW`로 처리한다.

## 5. 명칭 작성 규칙

### 5.1 한글 명칭

1. 위험 메커니즘 또는 침해 결과가 드러나는 자연스러운 명사구로 작성한다.
2. L3 마스터와 같이 분류 라벨 자체로 의미가 완결되면 `리스크`나 `위험`을 기계적으로 덧붙이지 않는다.
3. 다만 접미어를 제거하면 일반 활동·기술·대상과 혼동되거나 학술·정책 분야의 표준 용어가 훼손되는 경우에는 `리스크`, `위험`, `위해`, `피해`, `침해`를 유지한다.
4. 단순 분야명, 행위명, 기술명 또는 대상명으로 끝내지 않는다.
5. 어색한 직역 조어를 만들지 않는다.
6. AI 기본법, NIST AI RMF, OECD, ISO/IEC, UNESCO, EU AI Act 및 공신력 있는 안전 가이드라인에서 통용되는 용어를 우선한다.

### 5.2 영문 명칭

1. `risk`, `failure`, `harm`, `misuse`, `abuse`, `violation`, `infringement`, `bias`, `discrimination`, `exposure`, `leakage`, `degradation`, `loss`, `unsafe guidance` 등 위험을 나타내는 명사구로 작성한다.
2. 한글과 영문의 범위, 주체, 메커니즘 및 결과를 일치시킨다.
3. 정책·학술 문헌에서 통용되지 않는 직역 표현을 만들지 않는다.

## 6. 정의 작성 규칙

### 6.1 공통 구조

모든 정의는 L3 마스터의 문체와 동일하게 다음 구조를 사용한다.

> AI 시스템이 [실패·오용·부적절한 행동]하여 [영향 대상 또는 과정]에 [위해·피해·침해·안전 저하]를 초래하는 리스크.

영문은 다음 구조를 사용한다.

> The risk that an AI system [failure, misuse, or inappropriate behaviour], thereby [causal consequence and affected party].

### 6.2 정의 필수요소

1. 위험 주체
2. 위험 메커니즘
3. 적용 맥락 또는 작동 조건
4. 직접적 또는 합리적으로 예상 가능한 결과
5. 영향 대상
6. 마지막의 위험 표현

한국어 정의는 원칙적으로 `리스크.`, `위험.`, `위해.`, `피해.` 또는 `침해.`로 끝낸다. 영문 정의는 완결된 문장으로 작성한다.

### 6.3 금지사항

1. `콘텐츠`, `활동`, `분야`, `기능`, `능력`, `대응`, `조언`만 설명하고 위험을 명시하지 않는 정의
2. 원천에 없는 악의, 의도, 피해 또는 인과관계를 임의로 추가하는 정의
3. 동일 카드 안에 서로 다른 L3 메커니즘을 나열하는 정의
4. 한글과 영문의 의미 범위가 다른 정의
5. L3 정의를 그대로 반복할 뿐 L4의 구체성이 없는 정의

## 7. 정제 절차

### 단계 0. 원천 동결

1. CSV 5개와 PDF 6개를 별도 폴더에 복사한다.
2. SHA-256 manifest를 생성한다.
3. 모든 실행 전후에 원천 해시를 재검증한다.

### 단계 1. 구조 정규화

1. 도메인별 원천 스키마를 표준 내부 스키마로 변환한다.
2. 각 행에 고유 `source_row_id`를 부여한다.
3. Physical의 무시하기로 결정한 두 번째 빈 헤더 지시문은 포함하지 않는다.
4. facet과 act-type의 빈 값은 빈 상태로 유지한다.
5. ID가 `new`이거나 비어 있어도 원천 ID를 변경하지 않고 계보 필드에 보존한다.

### 단계 2. 명시적 Instruction Prompt 적용

적용 순서는 `DELETE`, `MERGE`, `SPLIT`, `DOMAIN_MOVE`, `REWRITE`, `RETAIN`이다. 지시문이 L3 마스터와 충돌하면 L3 마스터를 우선하고 충돌 사유를 기록한다.

### 단계 3. 리스크 적격성 심사

각 행에 다음 필드를 생성한다.

```text
risk_subject_present
risk_mechanism_present
adverse_outcome_present
causal_link_present
affected_party_present
topic_only_flag
protective_activity_flag
risk_eligibility_decision
risk_eligibility_reason
```

### 단계 4. 학술·정책 용어 기반 재작성

1. 인간 수정 설명이 유효한 경우 우선한다.
2. 기존 명칭과 정의에서 위험 메커니즘을 추출한다.
3. L3 문체에 맞춰 한글과 영문 명칭·정의를 재작성한다.
4. 사용한 표준 용어와 근거 출처를 행별 evidence ledger에 기록한다.
5. 출처를 확인할 수 없는 새 용어는 사용하지 않는다.

### 단계 5. 중복·통합·분리 검증

1. 명시적 통합·분리 지시를 우선 적용한다.
2. 제목 유사도가 아니라 위험 주체, 메커니즘, 결과, 영향 대상이 모두 같은 경우에만 중복으로 판정한다.
3. `정치적 성향`, `인종·민족`, `장애`, `성별·성정체성·성적 지향`에 근거한 적대·차별적 표상은 서로 다른 보호·사회적 특성에 대한 위해를 나타내므로 독립 L4 카드로 유지한다. 공통 문장 구조나 높은 임베딩 유사도만으로 이 카드들을 통합하지 않는다.
4. 삭제·통합·분리된 모든 원천 행은 별도 아카이브와 계보표에 남긴다.

### 단계 6. L1 도메인 라우팅

1. 명시적 도메인 이동 지시를 우선한다.
2. 지시가 없으면 원천 도메인을 기본값으로 사용한다.
3. 카드의 주체가 에이전트의 자율적 목표·계획·도구사용이면 Agentic 후보로 검증한다.
4. 물리적 감지·제어·행동·신체적 환경 작용이면 Physical 후보로 검증한다.
5. 디지털 콘텐츠 생성·처리 중심이면 General 후보로 검증한다.

### 단계 7. 제약조건 기반 L3 후보 생성

각 L3 정의에서 필수 포함조건과 제외조건을 생성한다. L4가 포함조건을 충족하지 못하거나 제외조건에 해당하면 해당 L3를 EM 후보에서 제거한다. Others는 EM 군집 중심에 포함하지 않는다.

### 단계 8. EM 기반 의미 매핑

1. 재작성 완료된 L4 명칭·정의만 임베딩한다.
2. 한글과 영문을 독립적으로 표현하고 결합 점수를 계산한다.
3. 도메인 내부의 적격 L3 후보에 대해서만 EM을 수행한다.
4. 여러 seed의 계산 안정성, 절대 점수, 1·2위 margin, 한영 일치도를 기록한다.
5. 안정성 통과와 별도로 L3 정의에 대한 의미 함의 검사를 수행한다.
6. 기준 미달 또는 경계성 카드는 도메인별 Others로 보내고 `HD`로 기록한다.

### 단계 9. ID 재발급

1. L1, L2, L3 ID는 동결된 마스터를 사용한다.
2. L4 ID는 최종 L3별 정렬 후 `L3_ID_순번` 형식으로 새로 발급한다.
3. 기존 ID와 `new` 값은 계보 필드에만 보존한다.
4. ID 재발급은 모든 삭제·통합·분리·매핑이 확정된 후 마지막에 수행한다.

## 9. 최종 릴리스 구조

최종 릴리스는 다음 5개 CSV로 구성한다.

1. `L1_Master.csv`
2. `L1_L2_L3_Master.csv`
3. `L4_General.csv`
4. `L4_Agentic.csv`
5. `L4_Physical.csv`

각 L4 CSV에는 L0·L1·L2·L3·L4의 ID, 한글·영문 명칭, 한글·영문 정의, facet, act-type, 매핑 방법, EM 진단값, HD 사유, 원천 계보, 변환 사유를 포함한다. Others 카드도 각 도메인 파일에 포함한다.

## 10. 검증 기준

### 10.1 원천 및 계보

1. 원천 해시 전후 일치
2. 모든 원천 `source_row_id`의 상태가 정확히 하나로 종결
3. 다대다 조인으로 인한 행 팽창 없음
4. 삭제 + 통합소멸 + 유지 + 분리 증감이 최종 합계와 일치

### 10.2 L3 마스터

1. 원천 L3 46행의 셀 단위 완전 일치
2. 파생 Others 3행 외 추가 L3 없음
3. L4의 모든 L3 외래키가 유효

### 10.3 리스크 문체

1. 한글 명칭이 L3와 같은 자연스러운 명사구이며 위험 메커니즘 또는 침해 결과를 식별할 수 있음
2. 한글 정의가 위험·위해·피해·침해 또는 리스크로 종결
3. AI 주체, 위험 메커니즘 및 부정적 결과 존재
4. 단순 주제·적용 영역 카드가 최종 L4에 잔존하지 않음
5. 한글·영문 의미 불일치 표본 및 자동 검사 통과

### 10.4 매핑

1. Violence 등 필수조건 L3의 제약 위반 없음
2. EM 계산 안정성과 의미 타당성을 별도로 기록
3. 경계성 카드가 강제 배정되지 않고 Others/HD로 이동
4. L3별 표본 수동 검토 가능

### 10.5 ID

1. 최종 L4 ID 전역 고유
2. L4 ID 접두부와 배정 L3 일치
3. 연속 순번과 결정적 재실행 보장
4. `new` 값이 최종 ID에 잔존하지 않음

## 11. 실행 중단 조건

다음 중 하나가 발생하면 릴리스를 생성하지 않고 검토 상태로 중단한다.

1. 원천 해시 불일치
2. L3 마스터 셀 변경
3. 계보 누락 또는 조인 팽창
4. 리스크 적격성 판정 없이 EM에 투입된 카드 존재
5. 필수조건을 위반한 L3 자동 배정
6. 한글·영문 정의의 의미 범위가 실질적으로 다름
7. 삭제 또는 재작성 근거가 기록되지 않음
