## 1. 검수 원칙

1. **전수(全數) 검사.** 표본이 아니라 808개 원천행 전부와 최종 카드 전부를 라인바이라인으로 대조한다. 스크립트는 대조표 생성·기계 검사에만 쓰고, **지시 이행 적합성 판정은 라인별 수기 판독**으로 한다.
2. **원본 대조.** 판정의 사실 근거는 KTSPACE CSV의 휴먼 검토의견 원문이며, Codex의 Summary·Ledger 서술은 주장으로만 취급하고 원천 데이터로 재확인한다.
3. **ID가 아닌 의미 기준.** 카드 추적은 계보(원장)와 명칭·정의 의미로 하고, ID 재번호를 감안한다.
4. **무변경 검수.** 검수 중 데이터 파일을 수정하지 않는다. 발견 사항은 판정 원장에만 기록하고 수정은 반려→Codex 재작업 경로로만 처리한다.
5. **이중 판정.** 에이전트 A(지시 이행 대사)·에이전트 B(문장·전거·원칙)가 독립 수행 후 불일치 건은 내가 재판정하고, 최종 FAIL/QUERY는 사용자에게 보고한다.

3. **포괄 카드 폐기 확인** — 모든 의미 조각이 흡수·분리된 뒤 원 포괄 카드가 폐기(ID 재사용 없음)되었는가. 의미 조각의 유실(어느 카드에도 귀속되지 않은 의미) = FAIL.

## 3. 판정·처리 규칙

| 판정 | 기준 | 처리 |
|---|---|---|
| PASS | 지시 취지 이행 + 원칙 준수 | 종결 |
| FAIL | 지시 불이행·오이행, 원칙 위반, 계보 유실, 무단 변경 | 검수 중단 없이 전수 완료 후 일괄 반려 목록으로 Codex 재작업 요청. 재작업 후 **해당 도메인 전체 재검수** |
| QUERY | 검토의견 해석 모호 | 사용자에게 원문·선택지 제시 후 결정 대기 |
| NOTE | 경미(비차단) | 기록 후 배포 허용, 차기 라운드 반영 |

**완료 기준:** FAIL 0 + QUERY 0(전부 결정 반영) + Phase 0~5 전체 PASS + 이중 판정 불일치 해소. 이후 최종 검수 보고서(`AUDIT_FINAL_REPORT.md`: 통계, 판정 분포, 반려 이력, 잔여 NOTE)를 작성해 사용자 승인을 받고, 승인 후에만 배포(commit·push는 사용자 수행).

## 4. 실행 역할 분담

- **기계 단계(Phase 0·3·5, Phase 1 대조표 생성):** 스크립트로 산출, 결과 CSV 고정.
- **에이전트 A:** Phase 1·2 전수 수기 판독(지시 이행 적합성).
- **에이전트 B:** Phase 4 전수 판독(언어·전거·톤) + Phase 1 중 문안 변경 행 교차 판독.
- **나(총괄):** A·B 불일치 재판정, QUERY 정리, 최종 보고서.
- 검수 산출물은 전부 본 폴더(`07_line_by_line_audit_claude/`)에 저장하며 Codex 작업 폴더는 읽기 전용으로만 접근한다.
